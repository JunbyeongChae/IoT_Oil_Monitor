# 🏗️ 시스템 상세 설계서 (HLD/LLD)

## 📌 1. 시스템 아키텍처 (High-Level Design, HLD)

### 1.1. 시스템 구성 다이어그램

본 시스템은 센싱, 처리, 장치간 통신, 사용자 알림의 4단계로 구성된 로컬 우선(Blynk 미사용) IoT 아키텍처를 채택한다. 1호기(센서)가 2호기(디스플레이)에 ESP-NOW로 직접 전송하고, 사용자에게는 텔레그램 봇으로 알림/조회를 제공한다.

| 구분 | 구성 요소 | 역할 |
| :--- | :--- | :--- |
| **센싱** | AJ-SR04M 방수 센서 | 기름 표면까지의 거리(L_air) 측정 |
| **처리 (1호기)** | ESP32-WROOM-32 | 측정값 수신, 잔량 계산 알고리즘 수행, 오류/저잔량 판정 |
| **장치간 통신** | ESP-NOW | 1호기 → 2호기, Wi-Fi 인프라 없이 직접 전송 (동일 채널 필요) |
| **사용자 알림/제어** | Telegram Bot API | 저잔량 자동 알림, `/status` 조회, `/reboot`, `/update` 원격 OTA |
| **UI/UX (2호기)** | TFT_eSPI 게이지 (ST7789 240x240) | 실내 실시간 잔량 표시, 온라인/오프라인 상태 |

### 1.2. 데이터 흐름 (Data Flow)

1.  **센싱:** AJ-SR04M이 초음파를 5회 발사, 중앙값으로 빈 공간 거리 ($L_{air}$) 측정.
2.  **처리:** 1호기가 $L_{air}$를 잔량 퍼센트($P$)로 변환. 무응답(에코 없음)이면 오류로 간주해 전송을 건너뛴다.
3.  **전송:** 1호기가 거리·퍼센트를 ESP-NOW로 2호기에 직접 전송 (약 1초 주기).
4.  **표시:** 2호기가 수신 즉시 TFT 게이지를 갱신, 60초 이상 미수신 시 OFFLINE 표시.
5.  **알림:** 1호기가 $P \le 15$ 진입 시 텔레그램으로 1회 알림, $P \ge 25$ 회복 시 재무장 (R-03).

## 📌 2. 하드웨어 상세 설계 (Low-Level Design, LLD)

### 2.1. 핀 맵 (Pin Map) 상세

| ESP32 핀 | AJ-SR04M 핀 | 연결 역할 | 기능/주의사항 |
| :--- | :--- | :--- | :--- |
| **GPIO 19** | **Trig** | 초음파 신호 출력 | 센서에 트리거 펄스 제공 |
| **GPIO 18** | **Echo** | 반사 신호 입력 | 수신된 신호 시간을 측정 (NewPing 라이브러리 사용) |
| **5V (or VIN)** | **VCC** | 전원 공급 | 센서 구동 전원 |
| **GND** | **GND** | 접지 | 공통 접지 |
| **USB-C** | N/A | 전원 입력 | 5V 3A C-Type 어댑터 사용 (NF-02 충족) |

### 2.2. 전원 및 패키징 설계 (NF-01, NF-02, NF-03 대응)

| 구성 요소 | 역할 및 상세 규격 | 설계 근거 |
| :--- | :--- | :--- |
| **패키징** | ABS 방수 정션 박스 | **IP66 등급** 확보를 통한 실외 환경 완벽 대응 (NF-01). |
| **전원 공급** | 5V 3A C-Type 어댑터 | 3m 이상 긴 케이블 환경에서 **전압 강하를 방지**하여 안정적인 ESP32 구동 보장 (NF-02). |
| **내부 결선** | 38핀 스크류 터미널 쉴드 | 납땜 없이도 **진동 및 습기에 강한** 견고한 연결 (NF-03). |
| **케이블 마감** | PG7, PG9 케이블 글랜드 | 전원선(PG7) 및 센서선(PG9)의 인장력 확보 및 방수 밀봉. |

## 📌 3. 소프트웨어 및 알고리즘 상세 설계 (LLD)

### 3.1. 잔량 측정 알고리즘

| 항목 | 기호 | 값 및 로직 | 설명 |
| :--- | :--- | :--- | :--- |
| **탱크 높이** | $H$ | 122 cm | 사용자가 정의한 탱크의 총 깊이 (데드존 20cm 포함) |
| **측정 거리** | $L_{air}$ | `sonar.convert_cm(sonar.ping_median(5))` | 5회 핑 중앙값 → cm 변환 (노이즈 억제) |
| **잔량 (%)** | $P$ | $P = \text{constrain}(\text{map}(L_{air}, 20, 122, 100, 0), 0, 100)$ | 빈 공간이 20cm면 100%, 122cm(바닥)면 0% |

### 3.2. 통신 및 로직 상세

* **ESP-NOW 전송 주기:** 약 1초 (`ESP_NOW_INTERVAL = 1000`), 2호기 화면 갱신용.
* **텔레그램 폴링 주기:** 3초 (`botRequestDelay = 3000`), blocking HTTPS 호출이라 ESP-NOW 주기를 방해하지 않게 여유를 둠.
* **잔량 부족 알림 (R-03):** 1호기가 자체 판단, $P \le 15$ 진입 시 텔레그램 알림 1회, $P \ge 25$ 회복 시 재무장 (히스테리시스로 중복 알림 방지).
* **NewPing 초기화:** `NewPing sonar(TRIGGER_PIN, ECHO_PIN, MAX_DISTANCE);` (MAX_DISTANCE = 400cm 설정)

### 3.3. 오류 처리 로직 (Data Validation)

1.  **측정 오류:** `ping_median()`이 0(에코 없음)을 반환하면 진짜 센서 오류로 간주해 **ESP-NOW 전송을 건너뛰고 마지막 정상값을 유지**한다. 연속 5회 실패 시 텔레그램으로 점검 알림을 보낸다. (탱크 바닥보다 먼 값은 오류가 아니라 constrain으로 0%에 매핑됨 — "가득 참"으로 오보하지 않는다.)
2.  **Wi-Fi 재접속:** 1호기는 `WiFi.begin()` 실패 시 재시도 루프(워치독 리셋 포함), 2호기는 `WiFi.reconnect()`로 재접속하여 ESP-NOW 채널 동기화를 유지한다.
3.  **ESP-NOW 채널 동기화:** 2호기도 1호기와 동일한 공유기에 STA로 접속해 같은 Wi-Fi 채널에 위치시킨다 (ESP-NOW는 동일 채널에서만 송수신 가능).

### 3.4. 원격 관리

* **로컬 OTA:** `ArduinoOTA`, mDNS 호스트명 `Oil_Level_Sensor.local`. 파티션은 `min_spiffs.csv` 사용 (OTA에 앱 슬롯 2개 필요, `huge_app.csv`는 1개뿐이라 사용 불가).
* **원격 OTA:** 텔레그램 `/update [URL]` → `HTTPUpdate`. 인증서 검증은 생략(`setInsecure()`)하는 대신 `github.com`/`objects.githubusercontent.com` 호스트만 허용.
* **텔레그램 명령:** `/status`(상태), `/reboot`(재부팅), `/update [URL]`(원격 업데이트). `CHAT_ID` 불일치 메시지는 무시.
